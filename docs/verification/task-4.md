# Task 4: security hardening

Before changes, the code already had bcrypt hashing, issuer/audience/algorithm/expiry validation for JWTs, membership checks, bounded HTTP/WebSocket input, and React text rendering. It had no refresh lifecycle, browser-origin allowlist, separate authentication abuse policy, or Nginx response security headers. No `dangerouslySetInnerHTML` or HTML injection is used to display message text.

Authentication now uses Redis IP and normalized-username windows, failure backoff, a five-failure username lock, bounded dependency errors, and `Retry-After`. The forwarded IP header is trusted only when the socket peer matches a configured proxy host's resolved address; default Compose restricts that trust to Nginx. Every WebSocket upgrade requires an exact allowlisted Origin, including native test/load clients. Production rejects short, known default, and repetitive JWT secrets. `node tools/init-env.mjs` generates JWT and optional database secrets into ignored `.env`; it preserves non-default values and does not inspect Grafana credentials.

Access JWTs last at most fifteen minutes. Refresh families expire absolutely after seven days by default, rotate atomically, record only hashes, detect spent-secret replay, and support logout revocation. A 4,096-rotation ceiling bounds each family document. Browser HTTP requests share renewal, WebSockets renew after expiry, and transient renewal errors retry. Logout clears local credentials after server confirmation; unsuccessful revocation is shown with a retry action. Already-issued access JWTs remain valid until expiry. Session storage limits persistence to the browser tab but does not protect secrets from XSS.

Nginx adds CSP, nosniff, referrer, permissions, framing, and conditional HSTS headers. TLS termination must overwrite `X-Forwarded-Proto`. The loopback stack still uses HTTP. The theme initializer is a same-origin external script, allowing a script CSP without inline execution. Existing body-size bounds remain; HTTP UTF-8 decoding is fatal, and message validation rejects malformed Unicode, NUL, and excessive UTF-8 bytes. Ordinary HTML-looking text remains text in React.

The initial full audit identified critical development-only Tinypool advisories through backend Vitest 3. Upgrading to Vitest 5.1.1 removed them. Both full dependency audits then reported zero vulnerabilities; CI fails on high severity. Backend tooling now requires Node.js 22.13+.

Done when: source checks, the new authentication/origin/refresh integration cases, existing integration and chaos cases, authenticated database boundary checks, and CI audit checks pass. Source checks passed with 82 backend and twelve frontend unit tests, formatting, lint, types, and builds. The ten existing integration cases passed, including 1,000 ordered messages in 91.18 seconds. The three new security cases passed after correcting test usernames that originally contained disallowed hyphens. Eleven smoke checks and [eleven actual proxy/header/theme assertions](security-headers.json) passed. All [four chaos cases](task-4-chaos/) passed across 485 sends with zero loss, logical duplicates, wire duplicates, or order violations. The processor was interrupted at 78 stored / 42 queued. Full dependency audits reported zero vulnerabilities in both applications. The optional database authentication proof passed before the non-root Redis setting was added; the later local retry ended during a cleanup timeout and is marked incomplete. CI runs the complete current proof, including the non-root check.

## Optional authenticated databases

Run `node tools/init-env.mjs`, then use `docker compose -f docker-compose.yml -f docker-compose.secure.yml up --build -d --wait`. Generated passwords are URL-safe hex. If supplying your own values, use URI-safe passwords or encode credentials appropriately. Keep `.env` private and use a deployment secret manager outside local development. The override enables MongoDB authentication and Redis password authentication; it does not add database TLS, replicas, or network isolation.

MongoDB's image creates its initial account only on an empty data directory. For an existing database, take a backup and provision the configured admin user before enabling `--auth`; do not delete data volumes to make initialization run again. An isolated proof uses fresh, uniquely named test volumes so the existing chat database remains intact. Redis retains AOF data when enabling its password. Host tools must use the authenticated connection URLs when this override is active.

Run `node tools/prove-database-auth.mjs` to reproduce authenticated/unauthenticated MongoDB and Redis checks in a fresh project. It checks project labels before deleting its own synthetic data and verifies Redis runs without root. CI runs the same proof. The initial attempt used TCP readiness and reached MongoDB during image initialization; the corrected probe waits for authenticated access and rejection of unauthenticated reads, rather than treating an open port as an initialized authentication system.

The lifecycle follows the rotation and replay-detection principles described in [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14); PulseChat is not presented as a complete OAuth authorization server. [Nginx header semantics](https://nginx.org/en/docs/http/ngx_http_headers_module.html) and [MongoDB atomic updates](https://www.mongodb.com/docs/manual/reference/method/db.collection.findoneandupdate/) inform the implementation.
